# 11 — دليل الفريق (Team Guide)

> موجّه لأي مطوّر جديد. بعد قراءة هذا الملف يجب أن تكون قادراً على العمل في المشروع دون أسئلة كثيرة.

---

## 1. قبل أي شيء

1. اقرأ `00_Project_Overview.md` ثم `07_Business_Logic.md` ثم `12_AI_MEMORY.md`.
2. شغّل المشروع محلياً (راجع `10_Deployment.md`).
3. لا تبدأ تعديلاً قبل فهم أثره على **الواجهات الثلاث** (Backend مشترك).

---

## 2. قاعدة العمل الإلزامية (Workflow) — لا استثناء

قبل أي تعديل، اتبع هذا التسلسل **دائماً**:

```
1) اقرأ التوثيق ذا الصلة.
2) نفّذ التعديل (بأصغر نطاق ممكن، وقابل للتراجع).
3) حدّث كل ملفات التوثيق المتأثرة.
4) حدّث 12_AI_MEMORY.md (إن تعلّمت شيئاً جديداً عن المشروع).
5) حدّث 13_CHANGE_LOG.md (إلزامي لأي تعديل مهما صغر).
```

إن مسّ التعديل **Business Logic / API / Database / Architecture**، حدّث ملفاتها المختصة أيضاً (`07`, `06`, `03`, `01`).

> **المشروع لا يُعتبر سليماً ما لم يطابق التوثيقُ الكودَ بنسبة 100%.** التوثيق جزء من المشروع لا إضافة اختيارية.

---

## 3. كيف تشغّل المشروع؟
راجع `10_Deployment.md`. باختصار: شغّل `backend` أولاً (`npm run dev`)، ثم الواجهة المطلوبة (`npm run dev`).

---

## 4. كيف تضيف API جديد؟ (Backend)

1. **النموذج:** إن احتجت بيانات جديدة، أضف/عدّل في `backend/src/models/`. تذكّر أثر التغيير على الواجهات الثلاث.
2. **الـ Controller:** أضف الدالة في `backend/src/controllers/<module>.controller.js` بنمط `try/catch` + JSON.
3. **الـ Route:** عرّف المسار في `backend/src/routes/<module>.routes.js`، وركّب الـ middleware الصحيح:
   - يحتاج تسجيل دخول؟ → `authMiddleware`.
   - يحتاج دوراً محدّداً؟ → `roleMiddleware(["..."])` **بعد** auth.
   - أدمن فقط؟ → `roleMiddleware(["admin"])` أو `adminMiddleware`.
4. **التسجيل:** إن كان ملف routes جديداً، سجّله في `server.js` تحت `/api/...`.
5. **التحقق من الملكية** عند الحاجة (نمط `Store.findOne({ owner: req.user.id })`).
6. حدّث `06_APIs.md`.

> ⚠️ احذر حساسية حالة الأحرف في `require` (أسماء الملفات الحقيقية: `ActivityLog.js`, `Cart.js`, `product.controller.js`...). الالتزام بالحالة الصحيحة ضروري للإنتاج على Linux.

---

## 5. كيف تضيف صفحة؟ (Frontend)

### الزبون (customerFrontend)
1. أنشئ `src/pages/MyPage.jsx`.
2. أضف `<Route>` في `src/App.jsx` (لفّها بـ `ProtectedRoute` إن كانت تتطلب تسجيلاً).
3. نادِ الـ API عبر `src/api/axios.js` (التوكن يُرفق تلقائياً).

### المتاجر (store-supplier-frontend)
1. أنشئ الصفحة في `src/pages/`.
2. أضف `<Route>` داخل قسمي `/store/*` و`/supplier/*` في `App.jsx` (غالباً تحتاج إضافتها في الموضعين).
3. استخدم خدمات `src/services/`.

### الأدمن (admin-panelFrontend)
1. أنشئ الصفحة في `src/pages/` وأضفها للراوتر و`Sidebar`.
2. استخدم `src/api/axios.js`.

---

## 6. كيف تعدّل قاعدة البيانات؟

1. عدّل الـ Schema في `backend/src/models/`.
2. **فكّر في التوافق الخلفي:** هل ستكسر بيانات موجودة؟ هل تحتاج migration؟
3. تأكّد أن كل controller يتعامل مع الحقل الجديد بشكل صحيح.
4. حدّث `03_Database.md` و(إن لزم) `07_Business_Logic.md`.
5. سجّل في `13_CHANGE_LOG.md` تحت قسم Database + هل يوجد كسر توافق.

> تذكّر: قاعدة البيانات **واحدة مشتركة** — أي تعديل يصل للواجهات الثلاث.

---

## 7. معايير كتابة الكود (Conventions الحالية)

- لغة رسائل المستخدم: **العربية**.
- نمط الـ controller: `exports.fn = async (req,res) => { try {...} catch {...} }`.
- الأسماء: ملفات النماذج تبدأ بحالة مختلطة (راجع الأسماء الفعلية بدقة).
- الحذف: soft (`isActive=false`) للمنتجات/العروض؛ راجع المنطق قبل اختيار hard delete.
- لا تُدخل أسراراً في الكود؛ استخدم `.env`.

> هذه المعايير **وصفية** (تصف ما هو قائم). أي توحيد/تحسين لها يُقترح ويُسجّل، ولا يُفرض بأثر رجعي دون اتفاق.

---

## 8. معايير الجودة (Quality Bar) — مقترحة

- لا تكسر الواجهات الثلاث: فكّر في الأثر المشترك.
- تعديلات صغيرة وقابلة للتراجع.
- اختبر يدوياً المسار المتأثر قبل الاعتماد.
- حدّث التوثيق مع كل تعديل (إلزامي).
- صنّف ملاحظاتك: 🔴 حرج / 🟡 مهم / 🟢 تحسين.

---

## 9. ماذا تفعل عند مواجهة سلوك غريب؟

1. راجع `15_BUGS.md` — قد يكون معروفاً (خصوصاً تضارب DrawBatch، حساسية الأحرف، ثغرات الصلاحيات).
2. راجع `07_Business_Logic.md` لفهم القاعدة المقصودة.
3. لا تفترض أن الميزة تعمل قبل التأكد (خصوصاً السحوبات).
